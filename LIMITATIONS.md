# Known limitations

| Area | Current behavior and consequence | Concrete next step |
| --- | --- | --- |
| Market source | Mock is the default and the only source the tests depend on. The optional Binance raw `@trade` adapter was verified by captured replay (including an injected disconnect), fake-socket lifecycle tests and five bounded live runs of about 3–7 minutes each. One run cut the network through a local relay: the service reconnected with backoff and reconciliation repaired the gap. `serverShutdown` and the 24-hour rotation were exercised only with fakes. Node's built-in WebSocket does not use HTTP proxies. | Multi-hour soak runs; proxy support through an explicit dispatcher if a deployment needs it. |
| Completeness | Live bars are `unverified` until reconciled. Flagged minutes (late, gap, startup, fault) are reconciled against Binance `aggTrades` and then equal the exchange's klines. Unflagged minutes are reconciled only with `--reconcile=all`, so a trade lost silently upstream in an unflagged minute stays undetected by default. Reconciliation trusts the venue's own history and its contiguous trade IDs; it cannot detect an error the exchange itself records. | Run `--reconcile=all` where the REST budget allows (one request per minute and symbol, more for busy minutes). |
| Late trades | The fixed receive deadline (default 2 s) still excludes delayed trades from the live bar; the minute becomes `known_incomplete` until reconciliation repairs it (live run 5 repaired BTCUSDT 16:06 from 2,499 to 5,073 trades). Without network access to the history, the exclusion stays flagged but unrepaired. | — |
| Numeric revision | Closed values change only through an explicit reconciliation revision (`valueRevision` increases, reason `repaired`). Consumers that require immutable history must pin the first revision. `qualityRevision` never decreases. | A versioned subscription or `sinceCommitSeq` query if consumers need to be told about revisions instead of polling. |
| Ingress durability | The FIFO exists only in memory. A crash can lose delivered but uncommitted events; restart gaps expose them, and reconciliation can repair those minutes afterwards. After a failed write, events queued behind it are not committed (they stay counted in `queueDepth`). | A durable ingress journal if replaying a restart gap from history is not acceptable. |
| Retention | Identities are pruned after 1 h by default. Bars and their quality evidence share a 7-day retained history window; expired history queries return HTTP 410 with `historyFloorMs`. The quality-event cap counts retained rows, so excessive churn within the window can still halt intake. SQLite reuses pages but may keep its file high-water size. Old schema files are refused; no migration is implemented. | Export history before expiry if longer retention is needed; use a fresh DB for this schema version. |
| Reconciliation scheduling | Failures retry with exponential backoff (15 s to 5 min) without a lifetime attempt cap. Automatic repair only considers the last 6 h; retry state resets at process restart. Each REST page has a 10 s deadline, with at most 60 pages, so one pathological minute can occupy a run for about 10 min. | Add a persisted repair backlog and REST rate-budget control for larger deployments. |
| Clock | Mock mode uses a virtual clock. Binance mode uses a wall-clock-anchored monotonic clock with a 1 s drift fault; host UTC accuracy is not proven, and the drift path is tested with an injected clock only. | Monitor time-sync uncertainty (e.g. chrony offset) and feed it into admission. |
| Storage | `node:sqlite` is experimental on Node 22. Tested: SQLite's own full error (page limit), a corrupt file, and a real OS ENOSPC on a 1 MB tmpfs in a Linux container. Power loss and torn writes are not tested. PID reuse may conservatively block a restart. | Power-loss testing on target hardware; a stable SQLite binding if operating requirements justify it. |
| Fault recovery | A persisted writer, resource, overflow or clock fault stays latched across restarts; there is no reset command. Reads remain available. | An audited reset procedure once the fault cause is identified and the stored prefix validated. |
| HTTP | Localhost read-only polling; no authentication, TLS, streaming output or durable subscription. | A versioned subscription contract only if required. |
| Scale | One process, one writer, at most two symbols. The synthetic benchmark measured about 2,000–2,300 trades/s in memory and 330–460 trades/s in file mode on this host; neither is a production SLA. | Profile representative bursts; consider bounded transaction batches with crash tests before partitioning. |
| Platforms | Verified on Windows (Node 22.16.0) and in a Linux container (Debian bookworm, Node 22.23.2), including the child-kill and ENOSPC tests. macOS and network file systems were not verified. | Run the extracted ZIP in macOS CI; keep file mode on a local disk. |
